# UX-11 — การมอบหมายงานและดึงงานที่ส่งตรวจกลับมาแก้ไข

## ขอบเขต
- ผู้มีสิทธิ์แก้ไขงานเลือกผู้รับผิดชอบได้จาก **บัญชีบุคลากรที่เปิดใช้งานจริง** เท่านั้น โดยแสดงชื่อจากโปรไฟล์ หากยังไม่ระบุชื่อจะใช้อีเมลบัญชี ไม่แสดง UUID เป็นคำอธิบายตัวเลือก
- ทะเบียนครูที่เตรียมไว้ 10 คนใน `private.staff_directory` ยังไม่ได้เชิญและไม่สามารถรับมอบหมายงานในระบบได้ จนกว่าจะมีบัญชีและสิทธิ์ที่ถูกต้อง
- ปุ่ม **ดึงงานกลับมาแก้ไข** ปรากฏเฉพาะเจ้าของงานที่สถานะ `submitted`; ผู้ตรวจยังไม่สามารถเห็นเป็นงานรอรับรองหลังดึงกลับ จนกว่าเจ้าของงานจะส่งใหม่

## สถานะและสิทธิ์
| สถานะก่อนหน้า | ผู้ดำเนินการ | สิ่งที่ทำได้ | ผลลัพธ์ |
|---|---|---|---|
| todo / doing / blocked | ผู้รับผิดชอบ | ส่งให้ตรวจ พร้อมสรุปงาน | submitted |
| submitted | ผู้รับผิดชอบเดิมเท่านั้น | ดึงกลับพร้อมเหตุผลบังคับ | doing |
| submitted | ผู้ตรวจที่ไม่ใช่เจ้าของงาน | ตรวจรับ | approved |
| submitted | ผู้ตรวจ | ส่งกลับพร้อมเหตุผล | doing |
| todo / doing / blocked | ผู้ตรวจที่มีสิทธิ์ | เปลี่ยนผู้รับผิดชอบพร้อมเหตุผล | สถานะเดิม |
| submitted / approved / cancelled | ผู้ตรวจ | เปลี่ยนผู้รับผิดชอบ | **ห้าม** |
| approved | ทุกคน | ดึงกลับ / เปลี่ยนงานหลังรับรอง | **ห้าม** |

## พฤติกรรมตรวจสอบย้อนหลัง
- คำสั่งดึงกลับเพิ่มรายการ `task_updates` และ `audit_events` ใหม่ โดยคงรายการส่งตรวจเดิมไว้ครบ
- เปลี่ยนผู้รับผิดชอบเพิ่มเหตุผล ชื่อเดิม-ใหม่ (ในข้อความสำหรับผู้ใช้) และรหัสภายในใน `audit_events` โดยไม่เปลี่ยนสถานะงาน
- ทุกคำสั่งเปลี่ยนข้อมูลใช้ `p_expected_version` และ `SELECT FOR UPDATE` เพื่อป้องกันคำสั่งเก่าทับผลตรวจรับล่าสุด
- ผู้ใช้ที่ไม่เข้าสู่ระบบไม่มีสิทธิ์เรียก RPC ใหม่; การอนุญาตระดับ role เพียงอย่างเดียวไม่เพียงพอ ต้องผ่านเงื่อนไขผู้รับผิดชอบหรือผู้ตรวจในฟังก์ชันด้วย

## การตรวจรับที่ยังเหลือ
1. บน iPhone เปิดงานที่ส่งตรวจด้วยบัญชีเจ้าของงาน: เห็น **ดึงงานกลับมาแก้ไข** แต่ไม่มีปุ่มอนุมัติงานตนเอง
2. เปิดเปลี่ยนผู้รับผิดชอบเมื่อ `submitted`: ไม่แสดงปุ่ม และแม้เรียก RPC โดยตรงก็ต้องถูกปฏิเสธ
3. เปิดงานที่ `doing` ด้วยผู้ตรวจ: ตัวเลือกแสดงชื่อจริง/อีเมล และข้อความว่ามีบัญชีเปิดใช้งานอยู่เพียงรายเดียว หากยังไม่มีครูที่เชิญแล้ว
4. หลังเชิญครูในอนาคต ให้ทดสอบด้วยบัญชีอื่นจริง: ผู้รับผิดชอบใหม่ต้องมีสิทธิ์ดูงาน ส่วนผู้ที่ไม่มีสิทธิ์ต้องไม่เห็น
5. ทดลองพิมพ์เหตุผลที่ว่าง การบันทึกข้อมูลเก่าจากอีกหน้าต่าง และการดึงกลับหลังผู้ตรวจรับรอง — ต้องถูกปฏิเสธ
6. ทดสอบประวัติเดิม/การเรียกดูหลักฐาน/การส่งตรวจใหม่หลังดึงกลับ พร้อมตรวจมือถือ Android

**ไม่ใช้ภารกิจจริงเป็นข้อมูลทดสอบอัตโนมัติ ไม่เปิด Auth ให้ครูโดยพลการ และไม่เปลี่ยนสถานะของงานจัดทำหนังสือขอบคุณในขั้นตอนออกเวอร์ชันนี้**

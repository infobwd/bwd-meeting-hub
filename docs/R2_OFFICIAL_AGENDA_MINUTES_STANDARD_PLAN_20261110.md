# BWD Meeting Hub — Official Meeting Agenda & Minutes Standard
Version: Planning 1.0 | Date: 2026-11-10 | **Plan only — not implemented / not an approved legal template**

## 1. Goal and boundaries
ให้โรงเรียนบ้านวังด้งใช้ข้อมูลประชุมชุดเดียวกันเพื่อเตรียมระเบียบวาระ จดรายงานการประชุม ติดตามมติ และส่งออกเอกสารราชการ โดยยังคงความแตกต่างระหว่าง **การประชุมที่โรงเรียนจัด** และ **รายงานผลการไปร่วมประชุมที่หน่วยงานอื่นเป็นเจ้าภาพ** (ดูแผน [External Meetings](R2_EXTERNAL_MEETINGS_AND_KNOWLEDGE_TRANSFER_PLAN_20261110.md)).

หลักอ้างอิงที่ต้องตรวจทานกับผู้รับผิดชอบงานสารบรรณก่อนใช้งานจริง: ระเบียบสำนักนายกรัฐมนตรีว่าด้วยงานสารบรรณ พ.ศ. 2526 และที่แก้ไขเพิ่มเติม โดยเฉพาะข้อ 25 / แบบที่ 11 (รายงานการประชุม) และข้อ 26 สำหรับบันทึกข้อความ; กฎหมาย/ระเบียบเฉพาะที่กำหนดอำนาจองค์ประชุมและการรับรองของคณะกรรมการแต่ละประเภท. **ไม่อ้างว่าการแบ่งวาระ 6 หมวดเป็นข้อบังคับตามระเบียบสารบรรณ**.

## 2. Default agenda template (configurable, not mandatory)
แม่แบบแนะนำสำหรับประชุมภายในโรงเรียน:
1. เรื่องที่ประธานแจ้งให้ที่ประชุมทราบ
2. เรื่องรับรองรายงานการประชุมครั้งที่ผ่านมา
3. เรื่องสืบเนื่องจากการประชุมครั้งที่ผ่านมา
4. เรื่องเสนอเพื่อทราบ
5. เรื่องเสนอเพื่อพิจารณา
6. เรื่องอื่น ๆ (ถ้ามี)

**Compatibility rule:** UI ปัจจุบันแสดงวาระ **5 หมวด** และตัวอย่างการประชุม 10 พ.ย. มี **13 เรื่อง** ตาม UX-02; ห้ามรีแมป/สลับ/ลบเรื่องเก่าโดยอัตโนมัติ. ใช้ `agenda_template_id` หรือ concept เทียบเท่าเป็นแม่แบบต่อการประชุม, เปิดแม่แบบ 6 หมวดเฉพาะรายการใหม่หลังอนุมัติ, และเก็บตัวเลือกแม่แบบเดิมไว้. คณะทำงาน/ประชุมภายนอกอาจไม่มีวาระครบทั้ง 6 หมวด.

### 2.1 Agenda entry data
- รหัส/ลำดับวาระ (เช่น 5.1), หัวเรื่อง, ผู้นำเสนอ
- ความเป็นมา, ข้อเท็จจริง, ข้อมูล/เอกสารที่อ้างอิง, ข้อเสนอและประเด็นขอความเห็น
- ประเภทการดำเนินการที่คาดหวัง (เพื่อทราบ / เพื่อพิจารณา / เพื่อติดตาม)
- สถานะร่าง/เผยแพร่วาระและประวัติการแก้ไข
- เอกสารแนบต้องใช้การอ้างอิงไฟล์ที่ตรวจสิทธิ์แล้ว ไม่เผยแพร่ลิงก์ส่วนตัวลง public repo

## 3. Formal minutes (แบบที่ 11)
รายงานการประชุมที่โรงเรียนหรือคณะประชุมรับผิดชอบการจัดทำควรรองรับองค์ประกอบต่อไปนี้:
- ชื่อการประชุม / ครั้งที่ / เมื่อ (วันเดือนปี) / ณ (สถานที่หรือรูปแบบออนไลน์)
- ผู้มาประชุม, ผู้ไม่มาประชุม (ถ้ามี), ผู้เข้าร่วมประชุม (ถ้ามี) พร้อมบทบาทและเหตุผลเมื่อเหมาะสม
- เริ่มประชุมเวลา
- เนื้อหาตามวาระ: ผู้เสนอเรื่อง, สาระสำคัญ, ประเด็นอภิปรายที่จำเป็น, **มติที่ประชุม** แยกจากข้อความร่าง/ข้อเสนอ
- เลิกประชุมเวลา
- ผู้จดรายงานการประชุม / ลายมือชื่อหรือวิธีลงนามที่ถูกต้องตามระบบเอกสารที่หน่วยงานยอมรับ

ช่องผู้ตรวจรายงาน/ผู้รับรองรายงาน/วันที่รับรองเป็นข้อมูลกระบวนการ **เพิ่มเติม** ไม่ใช้แทนส่วนประกอบของแบบที่ 11 หรือหลักฐานรับรองขององค์ประชุม. กำหนดเลขหน้า วันที่สร้างเวอร์ชัน และตราหน่วยงานเฉพาะเมื่อเหมาะสม; รูปแบบ A4 อ่านง่าย พิมพ์ขาวดำได้ และตรวจทานฟอนต์ราชการ.

## 4. Statements and decisions
- `รับทราบ` = รับข้อมูล ไม่เท่ากับเห็นชอบ
- `เห็นชอบ` = เห็นด้วยในเรื่องที่คณะนั้นมีอำนาจพิจารณา
- `อนุมัติ` = ใช้เฉพาะเมื่อมีอำนาจตามกฎหมาย/ระเบียบ ไม่ใช่ค่าเริ่มต้น
- `มอบหมาย` = ระบุรายละเอียดงานและผู้รับผิดชอบที่ยืนยันแล้ว
- `ให้ปรับปรุง/นำเสนอใหม่`, `ชะลอการพิจารณา` = บันทึกสถานะที่ยังไม่มีข้อยุติ
- ทุกมติต้องมี source meeting/agenda, เวลา, ผู้บันทึก, สถานะ draft/recorded/ratified และ audit trail; ถ้าต้องบันทึกองค์ประชุม/ผลลงคะแนนให้รองรับตามระเบียบเฉพาะของคณะนั้น

## 5. Review vs ratification
Flow สำหรับประชุมที่โรงเรียนเป็นเจ้าภาพ:
`ร่างวาระ → ตรวจวาระ → ประชุม → ร่างรายงาน → เลขานุการตรวจความครบถ้วน → ผู้บริหาร/ประธานตรวจทาน → เสนอให้คณะประชุมรับรองตามวิธีที่กำหนด → จัดเก็บฉบับรับรอง`.

**สำคัญ:** `reviewed` ของผู้บริหารในระบบปัจจุบันไม่ใช่ `ratified` โดยคณะประชุม; ห้ามเปลี่ยนสถานะย้อนหลังหรือสร้างมติรับรองอัตโนมัติ. กรณีมีข้อแก้ไขหลังรับรองให้สร้างรุ่นแก้ไข/ภาคผนวกพร้อมประวัติและวิธีรับรอง ไม่แก้ทับหลักฐานเดิมเงียบ ๆ.

## 6. Output and experience
- หน้าฟอร์มรองรับมือถือเป็นหลัก ใช้คำไทยที่อ่านเข้าใจง่ายและแสดงช่องจำเป็นตามชนิดการประชุม
- Export: PDF แบบราชการ, Google Docs (ต้องเชื่อมต่อ/กำหนดสิทธิ์ก่อน), และสรุปมติ/ภารกิจสำหรับใช้งานภายใน; **การพิมพ์ผ่าน browser PDF ปัจจุบันไม่ถือว่า Google Docs export มีแล้ว**
- การสร้างร่างด้วย AI ทำได้เฉพาะเมื่อได้รับอนุญาตและผ่านการตรวจทานโดยมนุษย์; ห้ามจัดทำมติที่ไม่มีหลักฐานหรือสรุปว่ารับรองแล้ว
- แสดงสถานะ: ฉบับร่าง / รอตรวจทาน / ผู้บริหารตรวจทานแล้ว / รอรับรองจากที่ประชุม / รับรองแล้ว อย่างถูกต้องตามข้อมูล

## 7. Proposed rollout (future)
- **DOC-00 — official template sign-off:** ให้เลขานุการ/ผู้อำนวยการยืนยันฟิลด์แบบที่ 11, ตัวอย่าง 6 วาระ, อำนาจหน้าที่/วิธีรับรองของแต่ละประเภทการประชุม และแนวทางลายมือชื่อ
- **DOC-01 — non-breaking data contract:** ออกแบบ template version, attendance, ratification metadata, minutes versioning, migration/rollback โดยไม่แตะ 13 เรื่องเดิม
- **DOC-02 — draft UI and previews:** พรีวิววาระและรายงานแบบมือถือ/พิมพ์ A4 โดยใช้ข้อมูลทดสอบสมมติ
- **DOC-03 — export and approval:** PDF และ Google Docs เฉพาะผู้มีสิทธิ์ พร้อม audit, PDF render regression, locked/immutable archival snapshot
- **DOC-04 — field acceptance:** ทดลองประชุมครูและประชุมคณะกรรมการกับบัญชีผู้ใช้หลายบทบาท ตรวจไฟล์จริง องค์ประชุม ลายเซ็น การแก้ไขเวอร์ชัน และ RLS
